# Security Policy

## About This Repository

This repository is a **public architectural overview** of a multi-tenant
Point-of-Sale and fiscal compliance platform. It contains **documentation only** —
no production source code, no deployment artifacts, and no live system endpoints.

The production platform is hosted privately and is **not** in scope for public
vulnerability reports through GitHub's infrastructure.

## Supported Versions

This repository publishes documentation only. There is no versioned software
to patch here. Documentation corrections are accepted via pull request.

## Reporting a Vulnerability

If you believe you have identified a security issue **in the production
platform** — for example, an authentication bypass, tenant-isolation flaw,
or fiscal-integrity weakness — please report it privately using one of the
channels below.

**Please do not open a public GitHub issue for security matters.**

| Channel | Details |
| :--- | :--- |
| **Email** | `security@<your-domain>` *(replace with your monitored address)* |
| **PGP Key** | *(optional — include fingerprint if you publish one)* |
| **Response SLA** | Initial acknowledgement within **72 hours** |

### What to include in your report

To help us triage quickly, please provide:

1. A clear description of the issue and its potential impact
2. Reproduction steps or a proof-of-concept (redacted if sensitive)
3. The affected component (e.g. authentication, real-time transport, fiscal journal)
4. Your contact details and preferred disclosure timeline
5. Whether you wish to be credited publicly

## Our Commitment

- We will acknowledge your report within **72 hours**
- We will provide an initial assessment within **7 days**
- We will keep you informed of remediation progress
- We will credit you publicly (with your permission) once a fix is deployed
- We will not pursue legal action against researchers acting in **good faith**

## Safe Harbor

We consider security research conducted in good faith — with the intent to
improve the security of the platform, without violating privacy, without
degrading service availability, and without exfiltrating data beyond what
is necessary to demonstrate the issue — to be **authorized conduct**.

We will not initiate or support legal action against researchers who:

- Report vulnerabilities privately and promptly
- Do not exploit an issue beyond what is needed to demonstrate it
- Do not access, modify, or delete user data belonging to others
- Do not degrade or interrupt live services

## Out of Scope

The following are **not** considered security vulnerabilities for the purposes
of this policy:

- Findings in third-party dependencies that have no demonstrated impact on this platform
- Missing security headers on static documentation pages
- Self-XSS or social-engineering attacks requiring user cooperation
- Volumetric denial-of-service attacks
- Reports generated by automated scanners with no demonstrated exploitability
- Issues requiring physical access to a cashier terminal

## Disclosure Policy

We follow a **coordinated disclosure** model:

1. Report received and acknowledged
2. Triage and validation
3. Remediation developed and deployed
4. Public disclosure coordinated with the reporter (typically 90 days after fix)
